### 2. Створення тестів

Було створено файл `test_app.py`. Pytest автоматично знаходить файли, назви яких відповідають шаблону `test_*.py`, а тестові функції повинні починатися з `test_`.

Приклад простого тесту:

```python
def test_triangle_type():
    triangle = Figure("трикутник", 4)
    assert triangle.type == "трикутник"
```

За допомогою `assert` перевіряється відповідність фактичного результату очікуваному.

---

### 3. Перевірка винятків

Для перевірки неправильних значень використано `pytest.raises`.

```python
def test_invalid_length():
    with pytest.raises(AssertionError):
        Figure("квадрат", 0)
```

Тест перевіряє, що під час створення фігури з неправильною довжиною виникає виняток `AssertionError`.

### 5. Параметризація тестів

Для перевірки всіх дозволених типів фігур було використано `pytest.mark.parametrize`.

```python
@pytest.mark.parametrize("figure", Figure.FIGURES)
def test_allowed_figure(figure):
    assert Figure(figure, 1).type == figure
```

Параметризація дозволяє виконати один тест для декількох наборів даних.

Таким чином не потрібно створювати окрему функцію для перевірки кожного типу фігури.

### 6. Створення fixture

Було створено fixture, яка повертає квадрат із довжиною сторони `10`.

```python
@pytest.fixture
def square():
    return Figure("квадрат", 10)
```

Після цього fixture можна передати безпосередньо в тест:

```python
def test_square_length(square):
    assert square.get_figure_length == 10
```

Pytest автоматично створює fixture та передає її результат у тест.

### 7. Fixture із залежністю

Було розглянуто можливість створення fixture, яка використовує іншу fixture.

```python
@pytest.fixture
def length():
    return 10


@pytest.fixture
def square(length):
    return Figure("квадрат", length)


def test_square_length(square):
    assert square.get_figure_length == 10
```

У цьому випадку fixture `square` залежить від fixture `length`.

Pytest сам визначає порядок їх створення.

### 8. Робота з тимчасовими файлами

Для роботи з тимчасовими файлами використовується вбудована fixture `tmp_path`.

Приклад:

```python
@pytest.fixture
def text_file(tmp_path):
    path = tmp_path / "result.txt"
    path.write_text("готово", encoding="utf-8")

    yield path

    path.unlink()


def test_text_file(text_file):
    assert text_file.read_text(encoding="utf-8") == "готово"
```

`tmp_path` створює окрему тимчасову папку для кожного тесту.

Після виконання тесту створений файл видаляється за допомогою:

```python
path.unlink()
```

---

### 9. Fixture з областю дії module

Було розглянуто використання параметра `scope`.

```python
@pytest.fixture(scope="module")
def allowed_figures():
    return Figure.FIGURES
```

Значення `scope="module"` означає, що fixture створюється один раз для всього тестового модуля.

Її можна використовувати в декількох тестах:

```python
def test_first(allowed_figures):
    assert "квадрат" in allowed_figures


def test_second(allowed_figures):
    assert "трикутник" in allowed_figures
```

### 10. Використання маркерів

Для групування тестів було використано маркер `unit`.

```python
@pytest.mark.unit
def test_triangle_type():
    triangle = Figure("трикутник", 4)
    assert triangle.type == "трикутник"
```

Маркер було зареєстровано у `pyproject.toml`:

```toml
[tool.pytest.ini_options]
markers = [
    "unit: швидкі юніт-тести",
    "slow: повільні тести"
]
```

Для запуску тільки тестів із маркером `unit` використовується:

```bash
pytest -m unit -v
```

### 11. Корисні команди pytest

Для роботи з тестами було розглянуто такі команди:

#### Перегляд знайдених тестів

```bash
pytest --collect-only
```

Команда показує тести, які pytest знайшов у проєкті, але не запускає їх.

#### Зупинка після першої помилки

```bash
pytest -x
```

Після першого невдалого тесту виконання припиняється.

#### Скорочений traceback

```bash
pytest --tb=short
```

Команда скорочує інформацію про помилку.

Також можна поєднати параметри:

```bash
pytest -x --tb=short
```

### 12. Навмисна помилка тесту

Для перевірки роботи pytest було навмисно змінено очікуване значення:

Фактична довжина дорівнює `10`, тому тест завершується зі статусом `FAILED`.

pytest зупиняє виконання після першої помилки та показує інформацію про причину невдалого тесту.

Після виправлення очікуваного значення тест знову проходить успішно.

## 13. Порівняння pytest та unittest

`unittest` є стандартною бібліотекою Python для написання тестів. При використанні `unittest` тести зазвичай створюються у класах, які успадковують `unittest.TestCase`.

Приклад `unittest`:

```python
import unittest


class TestFigure(unittest.TestCase):

    def test_triangle_type(self):
        triangle = Figure("трикутник", 4)
        self.assertEqual(triangle.type, "трикутник")
```

Аналогічний тест у `pytest`:

```python
def test_triangle_type():
    triangle = Figure("трикутник", 4)
    assert triangle.type == "трикутник"
```

Основні відмінності:

| unittest                                   | pytest                                 |
| ------------------------------------------ | -------------------------------------- |
| Використовуються класи `TestCase`          | Можна використовувати звичайні функції |
| Використовується `self.assertEqual()`      | Використовується звичайний `assert`    |
| Використовуються `setUp()` та `tearDown()` | Використовуються fixtures              |
| Менше можливостей параметризації           | Зручна параметризація                  |
| Входить до стандартної бібліотеки Python   | Встановлюється окремо                  |

`pytest` дозволяє писати більш короткі та зрозумілі тести, а fixtures і параметризація спрощують підготовку тестових даних.
